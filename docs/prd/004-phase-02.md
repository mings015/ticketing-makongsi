# PRD Phase 2 — Core Ticketing

## Goal

Menyediakan sistem pencatatan, pengelolaan, dan penyelesaian seluruh request IT dari semua unit bisnis.
Phase ini mencakup: manajemen ticket, assignment, komentar, dan attachment dalam satu flow terintegrasi.

---

## Roles & Permission Matrix

| Action | Employee | Support | Admin | Super Admin |
|---|:---:|:---:|:---:|:---:|
| Buat ticket | ✓ | ✓ | ✓ | ✓ |
| Lihat ticket milik sendiri | ✓ | ✓ | ✓ | ✓ |
| Lihat semua ticket | — | ✓ | ✓ | ✓ |
| Update ticket (title, desc, priority) | requester only | ✓ | ✓ | ✓ |
| Assign ticket | — | ✓ | ✓ | ✓ |
| Ubah status ticket | sesuai lifecycle | sesuai lifecycle | sesuai lifecycle | sesuai lifecycle |
| Hapus ticket (soft) | — | — | ✓ | ✓ |
| Kelola categories | — | — | ✓ | ✓ |
| Tambah komentar publik | ✓ | ✓ | ✓ | ✓ |
| Tambah internal note | — | ✓ | ✓ | ✓ |
| Upload attachment | ✓ (ticket milik sendiri) | ✓ | ✓ | ✓ |
| Hapus attachment | requester/uploader | ✓ | ✓ | ✓ |

Employee hanya bisa melihat ticket yang ia buat sendiri (requester).
Support melihat semua ticket yang di-assign kepadanya dan yang belum di-assign.

---

## Ticket Number Format

```
TKT-YYYYMM-NNNN

Contoh:
TKT-202601-0001   ← ticket pertama di Januari 2026
TKT-202601-0002
TKT-202602-0001   ← reset tiap bulan
```

Sequence di-generate di application layer dengan query `MAX(ticket_number)` per bulan.

## Endpoints

### Ticket Management

#### GET /tickets

List ticket dengan pagination dan filter.

Query params:
```
page:       number  (default: 1)
limit:      number  (default: 20, max: 100)
search:     string  (cari by title atau ticket_number)
status:     open | in_progress | pending | resolved | closed
priority:   low | medium | high | critical
categoryId: string  (UUID)
assigneeId: string  (UUID, "me" untuk ticket milik saya)
requesterId:string  (UUID)
```

Catatan:
- Employee: otomatis filter `requester_id = currentUser.id`
- Support: filter default ticket yang belum di-assign + ticket miliknya

Response `200`:
```json
{
  "data": [
    {
      "id": "uuid",
      "ticketNumber": "TKT-202601-0001",
      "title": "string",
      "status": "open",
      "priority": "medium",
      "category": { "id": "uuid", "name": "string" },
      "requester": { "id": "uuid", "fullName": "string" },
      "assignee": { "id": "uuid", "fullName": "string" } | null,
      "createdAt": "datetime",
      "updatedAt": "datetime"
    }
  ],
  "meta": { "page": 1, "limit": 20, "total": 100, "totalPages": 5 }
}
```

Permission: `tickets:read`

#### POST /tickets

Buat ticket baru.

Request body:
```
title:       string (min 5, max 255)
description: string (min 10)
priority:    low | medium | high | critical  (default: medium)
categoryId:  string (UUID, optional)
dueAt:       datetime (optional)
```

Flow:
1. Validasi input
2. Generate `ticket_number`: `TKT-{YYYYMM}-{NNNN}` (padded 4 digit)
3. Set `requester_id = currentUser.id`, `status = open`
4. Insert ticket
5. Buat notifikasi ke semua Support/Admin: `ticket_created`
6. Tulis audit log: `ticket.created`

Response `201`:
```json
{
  "id": "uuid",
  "ticketNumber": "TKT-202601-0001",
  "title": "string",
  "status": "open",
  "priority": "medium",
  "createdAt": "datetime"
}
```

Permission: `tickets:create`

---

#### PATCH /tickets/:id

Update informasi ticket (bukan status — ada endpoint terpisah).

Request body (semua optional, minimal satu field):
```
title:       string (min 5, max 255)
description: string (min 10)
priority:    low | medium | high | critical
categoryId:  string (UUID) | null
dueAt:       datetime | null
```

Guard:
- Employee hanya bisa update ticket miliknya sendiri saat status `open`
- Support/Admin bisa update kapan saja selama belum `closed`

Response `200`:
```json
{
  "id": "uuid",
  "title": "string",
  "priority": "medium",
  "updatedAt": "datetime"
}
```

Permission: `tickets:update`

---

#### PATCH /tickets/:id/assign

Assign atau reassign ticket ke support.

Request body:
```
assigneeId: string (UUID) | null  (null = unassign)
```

Flow:
1. Validasi assignee punya role `support` atau `admin`
2. Update `assignee_id`
3. Jika status `open` dan assignee tidak null → otomatis ubah ke `in_progress`
4. Notifikasi ke assignee baru: `ticket_assigned`
5. Notifikasi ke assignee lama (jika reassign): `ticket_updated`
6. Tulis audit log: `ticket.assigned`

Permission: `tickets:assign`

---

#### PATCH /tickets/:id/status

Ubah status ticket sesuai lifecycle.

Request body:
```
status: in_progress | pending | resolved | closed
note:   string (optional, untuk alasan perubahan status)
```

Flow:
1. Validasi transisi status sesuai lifecycle (lihat `docs/workflows/ticket-lifecycle.md`)
2. Validasi permission actor untuk transisi tersebut
3. Update status + timestamp (`resolved_at`, `closed_at`)
4. Jika ada `note`, buat internal comment otomatis
5. Kirim notifikasi sesuai transisi
6. Tulis audit log: `ticket.{status}`

Response `200`:
```json
{ "ok": true }
```

Errors:
- `400` — transisi tidak valid dari status saat ini
- `403` — role tidak boleh melakukan transisi ini

Permission: `tickets:update`

---

#### DELETE /tickets/:id

Soft delete ticket. Admin dan Super Admin saja.

Response `200`:
```json
{ "ok": true }
```

Permission: `tickets:delete`

### Comments

#### POST /tickets/:id/comments

Tambah komentar pada ticket.

Request body:
```
body:       string (min 1, max 5000)
isInternal: boolean (default: false)
```

Guard:
- `isInternal: true` hanya untuk Support, Admin, Super Admin
- Employee tidak bisa membuat internal note
- Ticket harus belum `closed`

Side effect saat Employee menambah komentar pada ticket berstatus `pending`:
→ otomatis pindah status ke `in_progress` (dianggap sebagai respons)

Response `201`:
```json
{
  "id": "uuid",
  "body": "string",
  "isInternal": false,
  "author": { "id": "uuid", "fullName": "string" },
  "createdAt": "datetime"
}
```

Permission: `tickets:read` (semua yang bisa lihat ticket bisa komentar)

---

#### PATCH /tickets/:id/comments/:commentId

Edit komentar. Hanya author komentar sendiri, selama belum 24 jam.

Request body:
```
body: string (min 1, max 5000)
```

Errors:
- `403` — bukan author atau sudah lewat 24 jam

---

#### DELETE /tickets/:id/comments/:commentId

Soft delete komentar. Author sendiri atau Admin/Super Admin.

### Attachments

#### POST /tickets/:id/attachments

Upload file attachment.

Request: `multipart/form-data`
```
file: File
```

Validasi:
```
Ukuran maksimal : 10 MB
Tipe yang diizinkan:
  - Gambar  : image/jpeg, image/png, image/gif, image/webp
  - Dokumen : application/pdf, application/msword,
              application/vnd.openxmlformats-officedocument.wordprocessingml.document,
              application/vnd.ms-excel,
              application/vnd.openxmlformats-officedocument.spreadsheetml.sheet
  - Teks    : text/plain
```

Flow:
1. Validasi mime type dan ukuran
2. Rename file → `{uuidv7}.{ext}` (tidak simpan nama asli sebagai storage key)
3. Upload ke S3/MinIO
4. Simpan metadata ke tabel `attachments`
5. Tulis audit log: `ticket.attachment_added`

Response `201`:
```json
{
  "id": "uuid",
  "fileName": "laporan-bug.pdf",
  "fileUrl": "https://storage.example.com/...",
  "fileSize": 204800,
  "mimeType": "application/pdf",
  "createdAt": "datetime"
}
```

Errors:
- `400` — tipe file tidak diizinkan
- `413` — file terlalu besar

---

## Status Lifecycle — Ringkasan

Lihat detail lengkap di `docs/workflows/ticket-lifecycle.md`.

| Dari | Ke | Actor |
|---|---|---|
| `open` | `in_progress` | Support, Admin, Super Admin (via assign) |
| `open` | `closed` | Admin, Super Admin |
| `in_progress` | `pending` | Support, Admin, Super Admin |
| `in_progress` | `resolved` | Support, Admin, Super Admin |
| `in_progress` | `closed` | Admin, Super Admin |
| `pending` | `in_progress` | Semua (via reply/comment) |
| `pending` | `closed` | Admin, Super Admin / auto-close 3 hari |
| `resolved` | `closed` | Employee, Admin, Super Admin / auto-close 3 hari |
| `resolved` | `in_progress` | Employee, Admin, Super Admin (reopen) |
| `closed` | — | Terminal, tidak bisa berubah |

## Security Implications

- Employee tidak boleh melihat ticket orang lain → filter wajib di repository, bukan hanya di controller
- Internal note tidak boleh terlihat Employee → filter `is_internal = false` untuk Employee
- File upload: validasi mime type di server (tidak percaya extension atau header dari client), scan konten jika tersedia
- File URL dari S3/MinIO harus menggunakan signed URL (time-limited) agar tidak bisa diakses tanpa autentikasi
- `ticket_number` harus unik — gunakan transaksi + retry jika terjadi race condition
- Semua transisi status wajib divalidasi di service layer, bukan di controller

---

## Database Implications

- Tabel `tickets`, `comments`, `attachments`, `categories` sudah terdefinisi di `docs/database/database-schema.md`
- Index yang sudah direncanakan: `status`, `requester_id`, `assignee_id`, `created_at`, `ticket_number`
- Index tambahan: `(status, assignee_id)` untuk query "ticket saya yang aktif"
- Transaksi wajib untuk: buat ticket + audit log + notifikasi, ubah status + audit log + notifikasi
- `ticket_number` di-generate dengan query `SELECT MAX(ticket_number) WHERE bulan = ?` dalam transaksi

---

## Performance Considerations

- List ticket: gunakan join tunggal untuk category + requester + assignee (hindari N+1)
- Attachment URL: jangan simpan URL signed — simpan path saja, generate signed URL on-demand
- Pagination wajib, default 20, max 100
- Comment di detail ticket: lazy load jika > 50 komentar (pagination komentar)

---

## Edge Cases

- Ticket number collision saat concurrent create: handle dengan retry dalam transaksi
- Assign ke user yang tidak aktif: tolak dengan `400`
- Comment pada ticket `closed`: tolak dengan `400`
- Employee upload attachment pada ticket orang lain: tolak dengan `403`
- Auto-close: actor_id di audit log = `null` (system action)
- Reopen resolved ticket setelah sudah auto-close: tidak bisa, buat ticket baru

---

## Acceptance Criteria

- Semua role dapat membuat ticket
- Ticket memiliki nomor unik format `TKT-YYYYMM-NNNN`
- Status lifecycle berjalan sesuai state machine
- Employee hanya melihat ticket miliknya sendiri
- Internal note tidak terlihat oleh Employee
- Support dapat assign dan ubah status ticket
- Admin dapat tutup ticket kapan saja
- Komentar tersimpan dan tampil berurutan
- File attachment divalidasi (tipe dan ukuran) sebelum disimpan
- Semua aksi penting tercatat di `audit_logs`
- Auto-close berjalan setelah 3 hari tidak ada aktivitas (via cron)
